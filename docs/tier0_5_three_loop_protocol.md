# Tier 0.5 Three-Loop Triage Protocol

This protocol diagnoses method generalization, measurement dependence, and real-checkpoint
engineering feasibility without running the scientific three-family pilot.

Loop A evaluates the frozen A0 audit on twelve unseen DGP families and four sample sizes. The
old six systems are regression fixtures only. Development and holdout differ in seeds, template
namespaces, shortcut markers, parser-corruption patterns, and entity permutations. The holdout
may be executed once only after the selected method is committed.

Loop B uses a new 160-scene, 480-probe measurement holdout, an independent scorer
implementation, clustered lower bounds, 240 adversarial parser responses, canonical fact-set
round trips, and a blinded human review packet. Automation cannot complete human review.

Loop C profiles three frozen, official open-weight checkpoints on development-only smoke cases.
It may report loadability, visual forward execution, contract integrity, determinism, resource
use, and artifact completeness only. It must not estimate behavioral evidence effects.

The old thresholds remain unchanged. At most one development-only AuditV2 repair is permitted.
No holdout result can change a threshold, SESOI, label, gate order, corruption, model, or prompt.

Passing all three loops authorizes only writing and freezing a preregistered scientific pilot;
it does not authorize running that pilot.
